# 版面設計規則：固定版型工具的取捨

寫 config 時的設計依據。優先順序：Figma Frame 的可驗證結構與尺寸 > 資訊傳達 > 內容配置 > 視覺層次 > 創意。沒有通過 node-specific Figma Frame gate 時，不建立生產版 config。

## 預設設計標準：mono-v1

使用者沒有指定風格時，固定採用 `config.designSystem.id = "mono-v1"`：紙色 `#f7f6f2`、墨色 `#171717`、灰階輔助文字與線條，最多一個可替換的中性強調色。介面 token 與海報 token 要同一套，避免預覽、表單與輸出各自長樣。
這是版本化起點，不是 Figma 來源的替代品。Figma Frame 已指定品牌色與樣式時，依 manifest 建立新的 design-system id 與 token，並在需求確認單記錄。

## Figma 來源的不可變規則

- 每個 `variant:<id>` 對應一個精確尺寸 Frame；Frame name、layer name 與 node ID 不用順序猜測。
- `field:<id>` 必須是真正 TEXT node；`image:<id>` 使用實際圖片填色／圖片或向量 node；`fixed:<id>` 不進表單；`module:<id>` 只綁自己的 variant 成員。
- 隱藏／未使用 layer 排除。mask、blend、fills、strokes、effects、opacity、rotation 與 z-order 以 manifest 為準；不支援的複雜效果要記錄 rasterization trade-off。
- Figma screenshot／full-frame export 是視覺正本。MCP 讀取出的座標與自動產生的 config 不能單獨證明像素一致，仍需 PNG overlay／difference 與人眼驗收。

提供 Figma Frame 或補充參考圖時，先讀 `references/reference-translation.md`。驗收結構、層級、網格、字體、色彩、人物處理與間距規格；補充截圖只能作方向，不是 Figma 來源或像素複製證據。

## 尺寸預設（px）

| 用途 | 尺寸 | 備註 |
|---|---|---|
| IG 貼文直式 | 1080 × 1350 | 預設首選，版面空間最多 |
| IG／FB／LINE 方形 | 1080 × 1080 | 店家公告常用 |
| IG 限動、Reels 封面、直式海報 | 1080 × 1920 | 上 250px、下 300px 會被介面蓋到，重要內容避開 |
| YouTube 封面 | 1280 × 720 | 右下角時間戳約 120 × 40 避開；主標要在 320px 寬的縮圖可讀 |
| FB 活動封面 | 1920 × 1005 | 手機會裁左右，重要內容放中間 1200px 內 |
| LINE 圖文訊息 | 1040 × 1040 | |
| X／Threads 橫式 | 1600 × 900 | |
| A4 直式列印 | 2480 × 3508 | 300 dpi；文字不小於 8pt（約 33px） |
| A3 直式列印 | 3508 × 4961 | 300 dpi |

使用者說不出尺寸就依平台提供建議，但生產輸出仍以 Figma Frame 實際尺寸為準。一個工具一個主要尺寸，其他精確尺寸用變體（`variant.size`）。Frame 與 manifest 的尺寸不一致時停止，不在程式中裁切或拉伸假裝通過。

## 安全邊界與留白

- 四邊留白至少短邊的 5%（1080 → 54px，建議 72 到 96）
- 同一層級的元素左緣對齊同一條線；先整齊再求變化
- 文字盒寬 ≤ 畫布寬 − 兩側留白；文字不要貼著照片邊

## 字級下限（1080 寬為基準，等比換算）

- 主標 80 到 110px、兩行內；副標 32 到 44px；資訊列（日期時間）44 到 60px；說明文字 28 到 34px；角落小字 ≥ 22px
- YouTube 1280 × 720：主標 ≥ 72px、12 字內；其他文字少放
- 列印 300 dpi：內文 ≥ 33px
- 每個變動文字都要同時有 maxLength（表單擋）與 maxLines 或 autoFit（畫面擋），兩道都要才不會破版

## 層級

- 一張圖一個主角：不是標題就是照片，不要兩個都最大
- 標題／副標／資訊三級要有明確的字級或字重差；同級同字級
- 關鍵數字放大（日期、價格、時間）、單位縮小

## 對比與照片上的文字

- 淺底淺字、深底深字直接不及格；說明文字對比至少 4.5:1
- 照片上放文字：先壓一層半透明色塊或漸層（rect 圖層，opacity 0.35 到 0.6）再放字，或加 stroke／shadow
- 使用者可上傳的背景照片預設 opacity 0.35 到 0.5 壓在深色底上，每張照片亮度不同也不會讓文字忽明忽暗

## 中文排版

- 行高：標題 1.15 到 1.3，說明 1.45 到 1.6；字距 0 到 0.05em，標題可略寬
- 全形標點；引擎已處理避頭點（標點不會跑到行首）
- 日期時間格式全站統一，例如「8/21（週五）20:00」或「8月21日 週五 20:00」，用 `{date:…}` `{time:…}` 寫死，不要讓使用者自己打
- 中英數字混排用同一字體家族；字體不超過 2 種（標題一種、內文一種）

## 色彩

- 主色＋強調色＋中性色，不超過 3 色
- 讓使用者換色只開一個「主色」欄位（color 欄位＋ 3 到 6 個色票），不要每個元素都能換
- 主色同時用在標籤底、日期文字、裝飾形狀，一致才有品牌感

## 照片

- 同一排人像同尺寸同形狀（圓形或同圓角）
- 人像圓形預設 focal (0.5, 0.35) 較容易對到臉；給使用者縮放與拖曳就夠，不要開放自由變形
- 圓形人像加 6 到 10px 白邊或品牌色邊，和深色底分離
- 沒上傳照片時畫面要能看（emptyFill＋placeholder）；匯出時空位不畫虛線框（引擎已處理）

## 固定 vs 變動的判準

- 問「下一張會改嗎」：不會 → 寫死在 layers；會但只在幾個選項內 → select 欄位；自由 → text 欄位
- 人數會變 → 做變體，不要做「隱藏第三位」；各變體各自排版
- 偶爾才有的元素 → 選填欄位＋ visibleIf
- 照片＋名字＋頭銜需要一起調整 → 用 variant-specific `modules` 綁定三個 layer，模組提供 x、y、scale；照片 layer 仍保留 focal／zoom／個別位置調整

## 既有畫面用渲染，不用生成

- 品牌素材、logo、既有海報的版面：照檔案或截圖重現，不用 AI 生圖
- AI 生圖只用在「還不存在的東西」（裝飾插畫），而且要先問過使用者

## 交付前六步檢查（對著匯出的 PNG 看）

1. 整體：3 秒內看得出這張圖在講什麼；底色與文字對比夠
2. 資訊：日期、時間、價格、CTA 都在；沒有錯字、簡體字、中國用語
3. 排版：行距字距舒服、有分字級、留白一致、換行合語意
4. 文字：照片上的字看得清楚；沒有被截斷的省略號
5. 視覺：顏色 ≤ 3、字體 ≤ 2、多張照片尺寸一致
6. 對齊：同一條線對齊；元素到邊框的距離一致
