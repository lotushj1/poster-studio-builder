# Poster Studio Builder：介紹與使用說明

把已經在 Figma 做好的固定海報，變成一個可以反覆使用的網站。之後只要在瀏覽器改標題、日期、照片這些會變的內容，就能預覽並下載 PNG 或 JPG。

這份文件給**第一次使用的人**：裝好公開 Skill 之後，用 Cursor、Claude Code 或 Codex，都能新建出這樣的網站。

- 公開 Skill：<https://github.com/lotushj1/poster-studio-builder>
- 用自己的 Figma Frame 建自己的網站，不要複製別人的現成專案。

## 這是什麼

一般做海報，每次都要回到 Figma 改字、換照片、再匯出。這個工具把「固定的設計」和「每次會變的內容」拆開：

- 版面、Logo、背景、不會變的裝飾：來自你的 Figma 完整畫面框（Frame）
- 標題、日期、來賓照片、說明文字：之後在網站上填

做出來的不是一張圖，而是一座小網站：左邊填、右邊看、確定後下載。

## 適合誰

- 設計師把同一套直播課、活動或公告版型交給團隊重複使用
- 內容創作者每週只換標題、日期、來賓照片
- 小型團隊要從同一張 Figma 版型輸出不同尺寸或不同人數

它**不會**替你設計海報，也不是自由排版工具。你要先有一張已經完成的 Figma 固定版型。

## 開始前準備

1. **Figma Frame 網址**  
   必須能實際開啟，而且直接指向那張海報。網址裡要有 `/design/` 和 `node-id=`，例如：  
   `https://www.figma.com/design/<檔案>/<名稱>?node-id=<數字>-<數字>`  
   只有截圖、參考圖或一般檔案網址不夠。
2. **使用權**  
   你要有權讀取這個 Frame，以及使用裡面的圖片、Logo、字體。連結打得開，不代表可以公開或商用。
3. **AI 工具（擇一即可）**  
   Cursor、Claude Code 或 Codex。三種都可以裝這個 Skill、建同一種網站。
4. **免費 [Cloudflare](https://dash.cloudflare.com/sign-up) 帳號**  
   用來把網站發到 `*.workers.dev`。第一次在那台電腦發佈時，要登入一次。

如果手上只有截圖，先回 Figma 找到對應的完整 Frame 和節點網址，不要請 AI 用截圖猜圖層位置。

## 第一步：安裝公開 Skill

對 Cursor、Claude Code 或 Codex **開一個新對話**，貼：

```
請安裝公開 Skill：https://github.com/lotushj1/poster-studio-builder
Skill 名稱 poster-studio-builder。
安裝後請告訴我，我會在下一則訊息用它。
```

Codex Desktop 也可以只貼 GitHub 網址，請它用內建安裝器安裝。

安裝完成後，**再開一個新對話**（或至少下一則訊息）再開始建站。不要把密碼、私人 Figma 連結或客戶照片放進公開 GitHub。

### 三種工具有什麼差別

三種工具走同一套規則，貼的話也一樣。差別只在安裝介面：

| 工具 | 怎麼裝 |
|---|---|
| Cursor | 新對話貼上面那段。它會把 Skill 裝到本機技能資料夾，下一則再請它建站。 |
| Claude Code | 同樣貼上面那段；或把這個 GitHub 專案放到 Claude 的 skills 資料夾後開新對話。 |
| Codex | 新對話貼 GitHub 網址，請它用 Skill Installer 安裝。下一個工作回合再使用。 |

裝好之後，三種工具都用下一節同一段「建站提示詞」。

## 第二步：請 AI 建一座新站

確認 Skill 已裝好。把 Figma Frame 網址換成你自己的，貼：

```
請使用 poster-studio-builder，用這個 Figma Frame 做一個海報產生器網站：
https://www.figma.com/design/<檔案>/<名稱>?node-id=<數字>-<數字>
發佈到 Cloudflare Workers（免費 workers.dev）。
```

補充這幾句會更準：

- 這張海報做什麼用（直播課、活動、公告）
- 哪些文字、日期、照片每次會換
- 哪些東西必須固定不動
- 要輸出幾種尺寸

AI 會先讀你的 Figma、整理會變與不會變的欄位，再請你確認。**確認前它不該直接開站。** 你要看它讀到的版面、欄位和固定素材是否正確。圖層名稱不清楚時，它會先提出命名建議，等你點頭才改。

不要請它去複製別人的現成專案。新站會建在你自己的資料夾，發到你自己的 Cloudflare。

## 第三步：檢查、發佈、拿到網址

1. 本機打開預覽，實際填一次內容、上傳一張照片、下載 PNG，打開檔案檢查。
2. 那台電腦第一次發佈：依 AI 指示登入 Cloudflare（通常是 `npx wrangler login`）。
3. 發佈後，它會給你一個 `https://<名稱>.<帳號>.workers.dev` 網址。請實際用瀏覽器打開確認。
4. 免費方案即可。自訂網域或登入牆先自己決定，不必一開始就買。

一張截圖或「測試通過」不能代替成品檢查。文字被截斷、照片裁切不對、尺寸不對，都不算完成。

## 第四步：以後怎麼用做好的網站

打開你的網站：

1. **內容**：填標題、說明、日期、時間。
2. **素材**：上傳或更換照片，在預覽圖上拖曳、縮放構圖。
3. **調整**：只動設計者開放的項目，例如字級、顏色、照片位置；也可以存常用內容。
4. **匯出**：選 PNG 或 JPG，下載目前版型，或分別下載全部版型。

預覽可以看「目前版型」或「全部版型」。全部版型會下載成多個檔案，不會打包成 ZIP。

使用者輸入和上傳的照片只留在**自己的瀏覽器**，不會上傳到這個網站的伺服器，也不會自動同步到其他裝置。清掉瀏覽器資料或換電腦前，先把需要的成品下載下來。

想改版型時，再給一個含 `node-id` 的 Figma Frame 網址，請同一個 AI 更新**已經存在的那座站**（要給它本機路徑或已驗證的網址，不要讓它猜）。

## 常見狀況

| 情況 | 怎麼做 |
|---|---|
| 只有截圖，沒有 Frame 網址 | 先回 Figma 找到完整畫面框，複製含 `node-id` 的網址。 |
| AI 說讀不到 Figma | 確認連結能開、對方有權限、網址是 `/design/` 不是舊的 `/file/`。 |
| 它開始複製別人的專案 | 停下，改叫它用這個 Skill 新建。 |
| 本機預覽好看、線上還沒更新 | 線上要另外發佈一次。沒發佈就不算大家看得到。 |
| 想再做第二座站 | 換一張 Figma Frame，再跑一次第二步。每座站各自有自己的資料夾與網址。 |

## 目前做不到的事

這不是自由拖曳排版工具。目前也不支援多頁編輯、雲端儲存、多人同步、AI 生圖、上傳字體檔、影片或動圖。

固定版型能不能完整重現，取決於 Figma 裡的字體、效果、素材和權限是否可用。缺字體或效果時，應標成尚未確認，不要說它和 Figma 完全一樣。
